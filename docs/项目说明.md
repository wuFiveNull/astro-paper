# AstroPaper 项目说明与技术现状

> 本文记录仓库当前实现，不把尚未开发的后端功能写成既有能力。开发目标另见[开发计划](./开发计划.md)。
>
> 文档更新时间：2026-09-26

## 1. 项目定位

AstroPaper 是一个基于 Astro 的博客主题。本仓库保留原有博客页面和主题组件，并正在升级为由 Spring Boot 与 MySQL 驱动的动态博客。

`src/content/posts/` 下的 Markdown/MDX 文件仍保留为迁移与回滚源；公开文章相关 Astro 页面现已切换为 Node SSR，并在每次请求时从 Spring API 获取文章、标签和搜索结果。仓库的 `backend/` 包含 Spring Boot 后端、Flyway 迁移、JPA 映射、公开文章 API、数据库认证与 RBAC 管理接口、评论/留言 API，以及文章导入准备工具。已有登录/账号/留言/评论页面及用户、角色权限和互动审核后台页面；文章管理界面和完整后台仍待实现。文章导入工具已在隔离云端 MySQL 验证，但生产数据库尚未导入。

后续目标是保留 Astro 的页面和视觉基础，将文章及互动数据迁移到 MySQL，由 Java + Spring Boot 提供业务 API。该目标处于分阶段实施中，尚未具备完整动态博客能力。

## 2. 当前技术栈

| 部分 | 当前实现 |
| --- | --- |
| 前端与页面生成 | Astro 7 SSR，Node adapter，pnpm 10.12.1 |
| 语言 | TypeScript；严格配置见 `tsconfig.json` |
| 样式 | Tailwind CSS 4，通过 Vite 插件集成 |
| 文章 | Astro Content Collections，支持 Markdown 与 MDX |
| 代码高亮 | Shiki 与自定义 transformer |
| 搜索 | 通过 Spring API 查询 MySQL |
| RSS | `@astrojs/rss`，服务端读取公开文章 API |
| SEO | robots.txt、动态 sitemap、Open Graph 与动态文章分享图 |
| 图片 | Sharp；动态 OG 图片使用 Satori 与 Sharp |
| 包管理 | pnpm；Node.js 引擎最低版本为 `>=22.12.0` |
| 代码检查 | ESLint、Prettier、`astro check` |
| 后端 | Spring Boot `4.1.1`、Java `21`、Maven；健康检查、公开文章 API、会话认证、管理员初始化和 RBAC 账号接口 |
| 数据库 | MySQL 8.4、Flyway、JPA；V1-V3、实体映射及公开查询已在云端隔离测试库验证 |

项目依赖和脚本以 [`package.json`](../package.json) 为准；主配置见 [`astro.config.ts`](../astro.config.ts)。

## 4. 内容模型与内容流程

迁移前，文章由 `src/content.config.ts` 定义为 `posts` 集合，文件加载器读取 `src/content/posts/` 中的 `.md` 和 `.mdx` 文件。该目录继续保留为迁移源。目标数据库字段包括：

- `title`、`description`、`author`
- `pubDatetime`、`modDatetime`、`timezone`
- `tags`、`featured`、`draft`
- `ogImage`、`canonicalURL`、`hideEditPost`

`draft` 文章会从公开文章列表、标签列表等公开集合中筛除；生产环境也会隐藏尚未到发布时间的文章，默认提前 15 分钟开放。文章 ID 与所在子目录共同决定文章 URL。

当前公开文章页面请求流程：

```text
浏览器请求 Astro 页面
        ↓ Astro Node SSR
Spring Boot 公开内容 API
        ↓
MySQL 查询文章、标签和搜索结果
        ↓
沿用 AstroPaper 页面组件与 Markdown 渲染规则输出 HTML
```

文章与标签数据的运行时读取已切换至 API；旧 Markdown/MDX 文件仍保留。导入准备工具已把当前 18 篇源文章写入隔离测试数据库，并在测试环境完成重复导入保护验证；生产数据库尚未导入。About 页面和迁移前的文件校验仍使用 Astro 内容集合。

## 5. 页面与路由

| 路径 | 用途 | 当前数据来源 |
| --- | --- | --- |
| `/` | 首页、精选和最近文章 | Spring API / MySQL |
| `/posts/`、`/posts/{页码}/` | 文章列表及分页 | Spring API / MySQL |
| `/posts/{slug}/` | 文章详情、标签、相邻文章、分享链接 | Spring API / MySQL |
| `/posts/{slug}/index.png` | 文章动态 OG 图片 | Spring API 的文章元数据 |
| `/og.png` | 默认动态 OG 图片 | 站点配置与字体资源 |
| `/tags/`、`/tags/{tag}/` | 标签列表及标签文章 | Spring API / MySQL |
| `/archives/` | 按时间分组的文章归档 | Spring API / MySQL |
| `/search/` | 数据库文章搜索 | Spring API / MySQL |
| `/about/` | About 页面 | `src/content/pages/about.md` |
| `/rss.xml` | RSS Feed | Spring API / MySQL |
| `/robots.txt`、`/sitemap.xml` | 搜索引擎抓取配置 | sitemap 在请求时读取 Spring API |
| `/404/` | 未找到页面 | 静态 Astro 页面 |
| `/api/v1/health` | 后端进程健康检查 | Spring Boot API |
| `/actuator/health` | 应用与数据库就绪状态 | Spring Boot Actuator |
| `/api/v1/auth/csrf`、`/login`、`/logout`、`/me` | CSRF、账号登录、退出和当前用户 | Spring Boot / MySQL |
| `/api/v1/admin/users` | 管理员分页查看/创建账号、调整状态和角色 | Spring Boot / MySQL，要求对应权限 |
| `/api/v1/admin/roles`、`/permissions` | 查看角色/权限并调整非管理员角色授权 | Spring Boot / MySQL，要求管理员权限 |

公开文章、列表与标签页面使用 SSR 路由，在请求时从 API 获取数据；不需要重新构建就能展示数据库中已发布的内容。尚未提供文章管理和数据库写入界面。

## 6. 主要配置

### `astro-paper.config.ts`

这是站点所有者优先修改的配置文件，包括：

- 站点 URL、名称、描述、作者、时区和语言
- 首页文章数量、分页数量和计划发布文章的宽限时间
- 暗色模式、归档、动态 OG 图、搜索等功能开关
- 社交链接、分享链接和文章编辑链接

仓库当前仍有 AstroPaper 示例站点 URL、主题示例作者和示例社交账号。部署正式站点前应替换为本站信息。

### `src/config.ts` 与 `src/content.config.ts`

`src/config.ts` 从用户配置读取设置并填充默认值；`src/content.config.ts` 定义内容加载器和字段校验。普通站点配置优先修改根目录的 `astro-paper.config.ts`。

### 环境变量

`astro.config.ts` 目前定义了可选公开变量 `PUBLIC_GOOGLE_SITE_VERIFICATION`。敏感密钥不能放进 `PUBLIC_` 变量，也不能提交到仓库。

## 7. 常用命令

```bash
pnpm install       # 安装依赖
pnpm dev           # 本地开发服务器
pnpm sync          # 生成 Astro 类型
pnpm run lint      # ESLint
pnpm run format:check  # 检查格式
pnpm run build     # Astro 类型检查与 SSR 构建
pnpm preview       # 预览构建产物
```

`build` 脚本会运行 `astro check` 和 `astro build`。运行时需要通过 `API_BASE_URL` 指定 Spring API 地址；Compose 测试配置使用内部服务地址 `http://api:8081`。

## 8. 当前构建、部署和 CI

- [`Dockerfile`](../Dockerfile) 使用 Node 构建 Astro SSR，并启动 Node standalone 服务；Spring Boot 仍单独运行。
- [`compose.yaml`](../compose.yaml) 是开发用途配置：挂载源码目录并运行 `pnpm dev --host 0.0.0.0`，不是完整生产环境。
- README 提到 Cloudflare Pages；仓库目前没有独立的自动部署工作流。
- [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 Pull Request、`workflow_call` 和 `main`/`codex/**` 分支 push 时运行；除前端 lint、格式检查和构建外，已加入 Java 21 后端构建与冒烟测试。
- 云服务器上已确认存在 Docker/Compose，现有网站容器使用 80 端口。后端在独立容器栈完成 V1-V3 迁移、健康检查和文章/标签/搜索接口验证；API 仅绑定本机回环地址。Astro SSR 页面已在隔离栈验证，文章详情和 OG PNG 正常；数据库导入工具已在隔离 MySQL 导入 18 篇测试文章、15 个标签和 33 条关联，并验证重复运行不改变数据。当前隔离栈已停止，命名卷保留测试数据；生产站点和数据库未导入新文章。
- 2026-09-26，云端认证冒烟测试使用独立 MySQL 与 API 容器通过；覆盖管理员初始化/登录、管理员创建普通账号、普通账号登录、权限拒绝和禁用账号会话失效。随机凭据、临时容器和专用测试数据卷已由脚本清理；生产站点与数据库仍运行，生产数据未改动。
- 评论与留言数据库 API 已实现并通过本地 H2 和云端隔离 MySQL 测试：登录用户提交评论/留言，评论需管理员或有审核权限的编辑者发布，留言只在后台可读/处理；云端测试资源已清理，生产数据未改动。
- Astro 已接入登录、当前账号、私密留言提交和文章评论；新增账号/状态/角色管理、非 ADMIN 角色权限配置、评论审核和留言处理页面。前端 ESLint 通过，`astro check` 与 SSR 构建均为 0 错误/警告/提示。
- 服务器内存有限；一次隔离 Web 镜像重建期间，内核日志记录生产 MySQL 进程被 OOM 终止两次并由 Docker 重启，生产应用出现连接池失效连接警告。复核时生产 MySQL ping 成功、网站应用仍响应。后续服务器侧构建/联调需控制内存占用，并在执行前核对生产服务状态。

## 9. 当前功能边界

**已有：**AstroPaper 主题页面与样式、About 页面、暗色模式和分享链接；文章列表、详情、标签、归档、数据库搜索、RSS、sitemap 与动态 OG 页面已改为 SSR 并调用公开 API。后端健康检查、MySQL/Flyway 表结构与种子、JPA 映射、公开读取 API、基于服务端会话的登录/退出、当前账号查询、一次性管理员初始化及角色/权限/账号管理 API 已实现。

**已有：**Markdown/MDX 导入准备工具；已对隔离 MySQL 验证 18 篇源文章与关系写入及重复导入失败保护。生产文章数据尚未迁移。

**尚未实现：**文章管理 API 与页面、登录限速、权限审计日志、评论/留言 UI 浏览器端联调、正式服务器部署与备份流程。认证、RBAC、评论和留言 API 已通过本地 H2 集成验证及云端隔离 MySQL 冒烟测试；Astro SSR 构建已通过，生产站点尚未切换到新 Astro/Spring 栈。

仓库内有介绍 Giscus 的文章，但它只是集成说明，不代表项目已经启用评论功能。

## 10. 敏感文件约定

`.gitignore` 已加入 `*.pem`。服务器 SSH 私钥应留在本机或受控密钥存储中，不能提交到 GitHub、写进文档或放入前端公开环境变量。数据库密码、会话密钥等也应仅通过服务器环境变量或受控秘密配置提供。
