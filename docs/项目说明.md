# AstroPaper 项目说明与技术现状

> 本文记录仓库当前实现，不把尚未开发的后端功能写成既有能力。开发目标另见[开发计划](./开发计划.md)。
>
> 文档更新时间：2026-09-25

## 1. 项目定位

AstroPaper 是一个基于 Astro 的博客主题。本仓库当前提供博客前端、静态文章内容、分类与搜索页面、RSS、SEO 元数据和构建部署配置。

当前内容以 `src/content/posts/` 下的 Markdown/MDX 文件为准，文章在构建时处理并生成静态页面。仓库已加入 `backend/` 下的 Spring Boot 后端，包括健康检查、Flyway 数据库迁移、JPA 实体/Repository 和公开文章读取 API。V1/V2 数据库迁移与实体校验已在云端隔离 MySQL 测试库验证；公开文章 API 与 V3 元数据迁移已本地构建通过，尚待云端验证。文章前端读取、MDX 转 Markdown 导入、登录与角色权限执行、动态评论/留言 API 尚未实现。

后续目标是保留 Astro 的页面和视觉基础，将文章及互动数据迁移到 MySQL，由 Java + Spring Boot 提供业务 API。该目标处于分阶段实施中，尚未具备完整动态博客能力。

## 2. 当前技术栈

| 部分 | 当前实现 |
| --- | --- |
| 前端与页面生成 | Astro，`package.json` 声明 `astro: ^7.0.3` |
| 语言 | TypeScript；严格配置见 `tsconfig.json` |
| 样式 | Tailwind CSS 4，通过 Vite 插件集成 |
| 文章 | Astro Content Collections，支持 Markdown 与 MDX |
| 代码高亮 | Shiki 与自定义 transformer |
| 搜索 | Pagefind 构建期索引 |
| RSS | `@astrojs/rss`，从文章集合生成 |
| SEO | Sitemap 集成、robots.txt、Open Graph 与动态文章分享图 |
| 图片 | Sharp；动态 OG 图片使用 Satori 与 Sharp |
| 包管理 | pnpm；Node.js 引擎最低版本为 `>=22.12.0` |
| 代码检查 | ESLint、Prettier、`astro check` |
| 后端 | Spring Boot `4.1.1`、Java `21`、Maven；健康检查与公开文章 API 已实现，未接入 Astro 页面 |
| 数据库 | MySQL 8.4、Flyway、JPA；初始表结构与实体映射已在云端隔离测试库验证，V3 及公开 API 查询待云端验证 |

项目依赖和脚本以 [`package.json`](../package.json) 为准；主配置见 [`astro.config.ts`](../astro.config.ts)。

```text

    ├── components/             # Header、Footer、Card、Pagination 等组件
    ├── content/
    │   ├── pages/              # About 等 Markdown 页面
    │   └── posts/              # Markdown/MDX 文章及文章图片

```

## 4. 内容模型与内容流程

文章由 `src/content.config.ts` 定义为 `posts` 集合，文件加载器读取 `src/content/posts/` 中的 `.md` 和 `.mdx` 文件。文章字段包括：

- `title`、`description`、`author`
- `pubDatetime`、`modDatetime`、`timezone`
- `tags`、`featured`、`draft`
- `ogImage`、`canonicalURL`、`hideEditPost`

`draft` 文章会从公开文章列表、标签列表等公开集合中筛除；生产环境也会隐藏尚未到发布时间的文章，默认提前 15 分钟开放。文章 ID 与所在子目录共同决定文章 URL。

当前内容生成过程：

```text
Markdown/MDX 文件
        ↓ Astro Content Collections 校验与编译
首页、列表、文章、标签、归档、RSS、OG 图片
        ↓ Pagefind 扫描生成搜索索引
静态 dist/ 目录
        ↓ Dockerfile 中的 Nginx 镜像
静态网站
```

文章集合目前是构建期数据源。新增或更新文章后需要重新构建，数据库尚未参与页面读取。

## 5. 页面与路由

| 路径 | 用途 | 当前数据来源 |
| --- | --- | --- |
| `/` | 首页、精选和最近文章 | 构建期文章集合 |
| `/posts/`、`/posts/{页码}/` | 文章列表及分页 | 构建期文章集合 |
| `/posts/{slug}/` | 文章详情、标签、相邻文章、分享链接 | 构建期文章集合 |
| `/posts/{slug}/index.png` | 文章动态 OG 图片 | 构建期文章元数据 |
| `/og.png` | 默认动态 OG 图片 | 站点配置与字体资源 |
| `/tags/`、`/tags/{tag}/` | 标签列表及标签文章 | 构建期文章集合 |
| `/archives/` | 按时间分组的文章归档 | 构建期文章集合 |
| `/search/` | Pagefind 搜索界面 | 构建期 Pagefind 索引 |
| `/about/` | About 页面 | `src/content/pages/about.md` |
| `/rss.xml` | RSS Feed | 构建期文章集合 |
| `/robots.txt`、sitemap XML | 搜索引擎抓取配置 | 静态文件/构建插件 |
| `/404/` | 未找到页面 | 静态 Astro 页面 |
| `/api/v1/health` | 后端进程健康检查 | Spring Boot API |
| `/actuator/health` | 应用与数据库就绪状态 | Spring Boot Actuator |

文章、列表与标签页面使用 `getCollection()` 和 `getStaticPaths()` 在构建时生成。动态读取数据库后，这些路由需要改成按请求获取数据或由前端调用 API。

## 6. 主要配置

### `astro-paper.config.ts`

这是站点所有者优先修改的配置文件，包括：

- 站点 URL、名称、描述、作者、时区和语言
- 首页文章数量、分页数量和计划发布文章的宽限时间
- 暗色模式、归档、动态 OG 图、搜索等功能开关
- 社交链接、分享链接和文章编辑链接

仓库当前仍有 AstroPaper 示例站点 URL、主题示例作者和示例社交账号。部署正式站点前应替换为本站信息。

### `src/config.ts` 与 `src/content.config.ts`

`src/config.ts` 从用户配置读取设置并填充默认值；`src/content.config.ts` 定义内容加载器和字段校验。普通站点配置优先修改根目录的 `astro-paper.config.ts`。

### 环境变量

`astro.config.ts` 目前定义了可选公开变量 `PUBLIC_GOOGLE_SITE_VERIFICATION`。敏感密钥不能放进 `PUBLIC_` 变量，也不能提交到仓库。

## 7. 常用命令

```bash
pnpm install       # 安装依赖
pnpm dev           # 本地开发服务器
pnpm sync          # 生成 Astro 类型
pnpm run lint      # ESLint
pnpm run format:check  # 检查格式
pnpm run build     # 类型检查、Astro 构建、Pagefind 索引
pnpm preview       # 预览构建产物
```

`build` 脚本会依次运行 `astro check`、`astro build`、Pagefind 索引，并将索引复制到 `public/pagefind/`。Pagefind 相关产物是构建结果，不是实时数据库搜索。

## 8. 当前构建、部署和 CI

- [`Dockerfile`](../Dockerfile) 使用 Node 构建 Astro 静态输出，再由 Nginx 托管 `dist/`。该镜像不运行 Spring Boot，也不提供 Astro SSR。
- [`compose.yaml`](../compose.yaml) 是开发用途配置：挂载源码目录并运行 `pnpm dev --host 0.0.0.0`，不是完整生产环境。
- README 提到 Cloudflare Pages；仓库目前没有独立的自动部署工作流。
- [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) 在 Pull Request、`workflow_call` 和 `main`/`codex/**` 分支 push 时运行；除前端 lint、格式检查和构建外，已加入 Java 21 后端构建与冒烟测试。
- 云服务器上已确认存在 Docker/Compose，现有网站容器使用 80 端口。后端已在独立容器栈完成 MySQL 迁移和健康检查；测试 API 仅绑定本机回环地址。测试完成后容器已停止以释放内存，MySQL 测试卷保留；现有网站和数据库容器未改动。

## 9. 当前功能边界

**已有：**静态文章、分页、标签、归档、Pagefind 搜索、RSS、sitemap、暗色模式、分享链接、动态 OG 图片、About 页面；后端健康检查、MySQL/Flyway 表结构与种子、JPA 映射，以及公开文章分页/详情/标签/搜索 API（API 暂未被前端调用）。

**尚未实现：**业务数据读写、用户注册/登录、后端授权执行、后台文章管理、数据库评论/留言 API、数据库搜索、服务端动态页面、生产服务器部署脚本。

仓库内有介绍 Giscus 的文章，但它只是集成说明，不代表项目已经启用评论功能。

## 10. 敏感文件约定

`.gitignore` 已加入 `*.pem`。服务器 SSH 私钥应留在本机或受控密钥存储中，不能提交到 GitHub、写进文档或放入前端公开环境变量。数据库密码、会话密钥等也应仅通过服务器环境变量或受控秘密配置提供。
